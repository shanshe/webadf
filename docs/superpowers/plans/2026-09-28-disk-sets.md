# Disk Sets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a person gather un-numbered disks, such as the AmigaOS 3.1.4 release, into one named, ordered "Disk set". The set is a title with several disks, so Next disk and the Next-disk card step through it. It can be built from an upload suggestion or by hand on the title page.

**Architecture:**
- A disk set IS a `games` row with several `disks` rows. Order is `disks.disk_no` (1..N). There is no new entity.
- Pure planners (`src/lib/disk-set.ts`, `src/lib/disk-set-suggest.ts`) decide every change.
- One store module (`src/lib/disk-set-store.ts`) applies each change as a single `db.batch`. That batch includes the device rows that name a moved disk.
- A new `games.disk_order_source = 'human'` protects an arranged set from TOSEC renumbering and duplicate merging.
- Web: a "Disk set" section on the title page, an Add-disks dialog, and an upload suggestion panel.

**Tech Stack:** Next.js app router (read `node_modules/next/dist/docs/` before touching routes and pages), Drizzle + Neon (neon-http: `db.batch`, no interactive transactions), zod, vitest, Playwright, Base UI, and dnd-kit (already used in `src/components/collections/collection-rail.tsx`).

**Spec:** `docs/superpowers/specs/2026-09-28-disk-sets-design.md`

**Mockup (approved):** `.superpowers/brainstorm/40506-1790627048/content/disk-set-title-page.html`

## Rulings made while planning

- **P1: No "type copied from the set".** Title type (Game/Demo/Utility) is derived (`src/lib/game-kind.ts`), not stored, so the spec's line "type copied from the set" on move-out has nothing to copy. Dropped.
- **P2: Folder name as a signal only when the browser gives one.** The folder-name signal is used only when `File.webkitRelativePath` is non-empty. A plain drag-and-drop gives none, so the version-tag and volume-pattern signals do the work.
- **P3: "Created by this drop" means `games.created_at >= since`.** The page sends `since`, the time the drop started, with its sha256s.
- **P4: Re-uploading a moved disk must not bring its old title back.** Ingest's deterministic game id would otherwise re-insert the deleted source title with no disks. After its disk inserts, ingest deletes any game it inserted in that call that has no disks (Task 6).
- **P5: Undo recreates the source title.** It restores title, sort title, year, publisher and metadata source under a new id. It does not restore covers, Demozoo links or collection memberships. The snapshot's `hadExtras` makes the toast say so.

## Review Focus

1. **A disk moved into a set while a board holds it.** The board keeps the disk, and "Next disk" follows the new numbering. Test: the route test asserts the device columns in the batch (Task 4); e2e also covers it (Task 10).
2. **Re-uploading a disk that is already in a set.** No empty or duplicate title appears (P4). Test: Task 6.
3. **TOSEC identifying a disk inside a human-arranged set.** Its number and title stay as the person set them, and the set is never merged away. Test: Task 5.
4. **A reorder that races another change** (for example, a disk moved out in another tab). The server refuses with 409 instead of numbering a stale list. Test: Task 4.
5. **Adding a multi-disk title into a set.** All its disks come across, in their order, after the set's last disk. Test: Task 2.

### Task 2: Pure planners, `src/lib/disk-set.ts`

**Produces:**

```ts
export type SetDisk = { id: string; gameId: string; diskNo: number };
export type DeviceRef = { id: string; desiredDiskId: string | null; mountedDiskId: string | null };
export type DeviceUpdate = { deviceId: string; desired?: { gameId: string; diskNo: number }; mounted?: { gameId: string; diskNo: number } };
export type Renumber = { diskId: string; gameId: string; diskNo: number };
export type Plan = { renumber: Renumber[]; emptiedGameIds: string[]; devices: DeviceUpdate[] };
export class PlanError extends Error { constructor(public code: 'stale_order' | 'nothing_to_add' | 'same_title') { super(code); } }
export function planAddDisks(target: { gameId: string; disks: SetDisk[] }, incoming: SetDisk[], allDisksOfSources: SetDisk[], devices: DeviceRef[]): Plan;
export function planReorder(target: { gameId: string; disks: SetDisk[] }, orderedIds: string[], devices: DeviceRef[]): Plan;
export function planMoveOut(disk: SetDisk, newGameId: string, remaining: SetDisk[], devices: DeviceRef[]): Plan;
```

Semantics:
- **`planAddDisks`:**
  - `incoming` is the disks the person picked. For each picked disk, all disks of its source title are moved, in the source's `diskNo` order. `allDisksOfSources` supplies them.
  - The moved disks are appended after `max(target.diskNo)` in the order their source titles were first picked.
  - Each source title that ends up with no disks goes into `emptiedGameIds`.
  - A disk already in the target throws `same_title`. An empty result throws `nothing_to_add`.
- **`planReorder`:** the ids must be exactly the target's current disk ids, as a set with the same count. Otherwise it throws `stale_order`. The result is renumbered 1..N in list order.
- **`planMoveOut`:**
  - The disk goes to `newGameId` with diskNo 1.
  - The remaining disks of the old title are renumbered 1..N, keeping their relative order.
  - If none remain, the old title goes into `emptiedGameIds`.
- **Devices:** for each device whose `desiredDiskId` or `mountedDiskId` is a renumbered disk, emit the matching `desired` or `mounted` update with the disk's new `{gameId, diskNo}`.

```ts
/**
 * Disk sets (spec 2026-09-28-disk-sets §2): every change to which title a disk
 * belongs to, or to its number, is planned here -- pure, so the rules are
 * tested without a database. disk-set-store.ts applies a Plan as one batch.
 */
export type SetDisk = { id: string; gameId: string; diskNo: number };
export type DeviceRef = { id: string; desiredDiskId: string | null; mountedDiskId: string | null };
export type DeviceUpdate = { deviceId: string; desired?: { gameId: string; diskNo: number }; mounted?: { gameId: string; diskNo: number } };
export type Renumber = { diskId: string; gameId: string; diskNo: number };
export type Plan = { renumber: Renumber[]; emptiedGameIds: string[]; devices: DeviceUpdate[] };

export class PlanError extends Error {
  constructor(public code: 'stale_order' | 'nothing_to_add' | 'same_title') { super(code); }
}

const byNo = (a: SetDisk, b: SetDisk) => a.diskNo - b.diskNo || (a.id < b.id ? -1 : 1);

function deviceUpdates(renumber: Renumber[], devices: DeviceRef[]): DeviceUpdate[] {
  const to = new Map(renumber.map((r) => [r.diskId, { gameId: r.gameId, diskNo: r.diskNo }]));
  const out: DeviceUpdate[] = [];
  for (const dev of devices) {
    const desired = dev.desiredDiskId ? to.get(dev.desiredDiskId) : undefined;
    const mounted = dev.mountedDiskId ? to.get(dev.mountedDiskId) : undefined;
    if (desired || mounted) out.push({ deviceId: dev.id, ...(desired ? { desired } : {}), ...(mounted ? { mounted } : {}) });
  }
  return out;
}

export function planAddDisks(
  target: { gameId: string; disks: SetDisk[] }, incoming: SetDisk[], allDisksOfSources: SetDisk[], devices: DeviceRef[],
): Plan {
  if (incoming.length === 0) throw new PlanError('nothing_to_add');
  if (incoming.some((x) => x.gameId === target.gameId)) throw new PlanError('same_title');
  const sourceOrder: string[] = [];
  for (const x of incoming) if (!sourceOrder.includes(x.gameId)) sourceOrder.push(x.gameId);
  let next = target.disks.reduce((m, x) => Math.max(m, x.diskNo), 0);
  const renumber: Renumber[] = [];
  for (const g of sourceOrder) {
    for (const x of allDisksOfSources.filter((y) => y.gameId === g).sort(byNo)) {
      renumber.push({ diskId: x.id, gameId: target.gameId, diskNo: ++next });
    }
  }
  return { renumber, emptiedGameIds: sourceOrder, devices: deviceUpdates(renumber, devices) };
}

export function planReorder(target: { gameId: string; disks: SetDisk[] }, orderedIds: string[], devices: DeviceRef[]): Plan {
  const current = new Set(target.disks.map((x) => x.id));
  const given = new Set(orderedIds);
  if (orderedIds.length !== target.disks.length || given.size !== orderedIds.length
      || [...given].some((id) => !current.has(id))) throw new PlanError('stale_order');
  const renumber = orderedIds.map((id, i) => ({ diskId: id, gameId: target.gameId, diskNo: i + 1 }));
  return { renumber, emptiedGameIds: [], devices: deviceUpdates(renumber, devices) };
}

export function planMoveOut(disk: SetDisk, newGameId: string, remaining: SetDisk[], devices: DeviceRef[]): Plan {
  const renumber: Renumber[] = [{ diskId: disk.id, gameId: newGameId, diskNo: 1 }];
  [...remaining].sort(byNo).forEach((x, i) => renumber.push({ diskId: x.id, gameId: disk.gameId, diskNo: i + 1 }));
  return { renumber, emptiedGameIds: remaining.length === 0 ? [disk.gameId] : [], devices: deviceUpdates(renumber, devices) };
}
```

### Task 3: The upload suggestion, `src/lib/disk-set-suggest.ts`

**Produces:**

```ts
export type SuggestInput = { diskId: string; gameId: string; filename: string; volumeName: string | null; relativePath?: string };
export type Suggestion = { name: string; disks: Array<{ diskId: string; gameId: string; label: string; ticked: boolean }> } | null;
export function releaseTag(s: string): string | null;   // "Install3_1_4.adf" -> "3.1.4"; "ModulesA1200_3.1.4.adf" -> "3.1.4"; "Fonts.adf" -> null
export function suggestSet(files: SuggestInput[]): Suggestion;
```

Rules (spec §3; P2):
- **Tag:** the first `\d+(?:[._]\d+){1,3}` in the name without its extension, with `_` normalised to `.`. It is taken from the volume name, else the filename.
- **The winning tag** is the one shared by the most disks, if that is at least 2. When no tag is shared by 2 or more, but a non-empty `relativePath` folder is shared by every disk, the folder name is used as the name and every disk is ticked. Otherwise the result is `null`.
- **Ticked:** disks carrying the winning tag, or in the shared folder. Other disks in the input are listed unticked.
- **Name:**
  - the folder name if shared;
  - else `AmigaOS <tag>` when any filename or volume contains "amigaos" (any case), or any volume or filename starts with `Workbench` or `Install`;
  - else `<tag> set`.
- **Label:** the volume name if known, else the filename without its extension.
- **Order:** `Install*` first, then `Workbench*`, then the input order. Unticked disks come last.
- **Size:** fewer than 2 files, or more than 32, gives `null`.

**Produces:**

```ts
export type UndoSnapshot = { diskIds: string[]; title: string; sortTitle: string; year: number | null; publisher: string | null; metadataSource: string | null; hadExtras: boolean };
export async function addDisksToSet(orgId: string, gameId: string, diskIds: string[], rename?: string): Promise<{ undo: UndoSnapshot[] }>;
export async function reorderSet(orgId: string, gameId: string, orderedIds: string[]): Promise<void>;
export async function moveDiskOut(orgId: string, diskId: string): Promise<{ gameId: string }>;
export async function undoMove(orgId: string, snap: UndoSnapshot): Promise<{ gameId: string }>;
export class NotFound extends Error {}
```

Behaviour:
- **Every read is org-scoped** (`eq(x.orgId, orgId)`). A missing target or disk throws `NotFound`.
- **`addDisksToSet`:**
  - Reads the target's disks, the picked disks, all disks of their source titles, and the org's devices (`id`, `desiredDiskId`, `mountedDiskId`).
  - Calls `planAddDisks`.
  - Snapshots each emptied source title: `title`, `sortTitle`, `year`, `publisher`, `metadataSource`, its disk ids, and `hadExtras = coverAssetId !== null || demozooProductionId !== null || (it has collection_games rows)`.
  - Then one batch:
    1. `update disks set game_id, disk_no` per renumber;
    2. device updates per plan;
    3. `update games set disk_order_source='human'` on the target, and when `rename` is given also `title`, `sortTitle = makeSortTitle(rename)` and `metadataSource = 'human'`;
    4. `delete from collection_games where game_id in emptied`;

- **`moveDiskOut`:**
  - Reads the disk and its title's other disks.
  - The volume name is read with `readVolume(await diskStore.read(sha))`; if `ok`, `v.volume.name` is the title. Otherwise the fallback is the entitlement's `sourceFilename` without its extension, else `Disk`.

- **`undoMove`:**
  - Re-checks that every `snap.diskIds` disk is in the org; otherwise `NotFound`.
  - Inserts a new game from the snapshot with id `stableId('game', orgId, 'undo', snap.diskIds.join(','), String(Date.now()))`.
  - Moves those disks there, numbered 1..N in snapshot order. The titles they leave are renumbered 1..N, and a title left with no disks is deleted.
  - Device updates in the same batch.
